# Алгоритмы формирования платформенных индексов

Документ фиксирует правила формирования индексов таблиц базы данных объектов метаданных
и алгоритмы их расчёта в модели MDClasses. Для каждого объекта метаданных приведены правила,
для каждого правила — полный состав индекса и условие из документации платформы, алгоритмы
формирования и статус включения в модель.

Документ является чек-листом трассировки: правило → алгоритм → ветка калькулятора → эталонный объект в тестах.

_Источник правил: 1С:Предприятие 8.3.27, методическая поддержка для разработчиков и администраторов (its.1c.ru, раздел «Индексы таблиц базы данных»)._

## Общие соглашения

### Разделители

Во все индексы объекта первыми полями входят общие реквизиты, являющиеся разделителями
данного объекта в режиме «Разделять независимо»: общие реквизиты конфигурации, у которых
свойство «Разделение данных» равно `SEPARATE_INDEPENDENTLY` и данный объект входит
в их состав (список использования). В составе индекса обозначаются `[ОРНР…]`.

Часть условий документации описывает выбор между полем конкретного разделителя (`ОРНР1`)
и полем хэш-функции значений разделителей (`ОРРХ`). Хэш (`ОРРХ`) — физическое представление
индекса в СУБД и в модели не строится: во всех таких случаях в индекс включаются все
независимые разделители объекта.

### Легенда

- ✅ — правило включено в модель;
- ❌ — правило исключено из модели с указанием причины;
- `codeLength`, `descriptionLength`, `numberLength`, `orderLength` — соответствующие свойства длины объекта;
- `mainPresentation` — свойство «Основное представление» (`AS_CODE` / `AS_DESCRIPTION`);
- `indexing` — свойство «Индексировать» реквизита/графы (`INDEX` / `INDEX_WITH_ADDITIONAL_ORDER`);
- `master` — свойство «Ведущее» измерения;
- `foldersOnTop` — свойство «Размещать группы сверху»;
- `writeMode` — режим записи регистра сведений (`INDEPENDENT` / `RECORDER_SUBORDINATE`);
- `periodicity` — периодичность регистра сведений;
- `correspondence` — свойство «Корреспонденция» регистра бухгалтерии;
- `actionPeriod` — свойство «Период действия» регистра расчета.

## Справочник

### Основные индексы

#### Правило 1 — [ОРНР1 + ... +] Ссылка (Кластерный)

Условие: Всегда. В индекс входят поля независимых разделителей, которые разделяют этот справочник.

Алгоритм 1.1: Создать индекс состава [ОРНР…] + Ссылка, кластерный.

Статус: ✅

#### Правило 2 — [ОРРХ | ОРНР1 +] Код + Ссылка

Условие: Свойство "Длина кода" не равно 0. Если справочник разделяется одним независимым
разделителем, тип которого не Строка, то индекс содержит поле этого разделителя. Если тип
разделителя - Строка, или разделитель независимый и совместный, или разделителей больше
одного, то индекс содержит поле значения хэш-функции значений разделителей. Это правило
справедливо для всех индексов, в составе которых указано [ОРРХ | ОРНР1 +].

Алгоритм 2.1: Если `codeLength != 0` — создать индекс состава [ОРНР…] + Код + Ссылка.
Выбор между полем разделителя и хэшем (часть условия про ОРРХ) не моделируется:
включаются все независимые разделители объекта.

Статус: ✅

#### Правило 3 — [ОРРХ | ОРНР1 +] Наименование + Ссылка

Условие: Свойство "Длина наименования" не равно 0.

Алгоритм 3.1: Если `descriptionLength != 0` — создать индекс состава [ОРНР…] + Наименование + Ссылка.

Статус: ✅

#### Правило 4 — [ОРРХ | ОРНР1 +] Реквизит + Ссылка

Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение "Индексировать".

Алгоритм 4.N: Для каждого реквизита справочника с `indexing == INDEX` — создать индекс
состава [ОРНР…] + Реквизит_N + Ссылка.

Статус: ✅

#### Правило 5 — [ОРРХ | ОРНР1 +] Реквизит + Код + Ссылка

Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение
"Индексировать с доп. упорядочиванием" и при этом свойство "Длина кода" не равно 0,
а свойство "Основное представление" равно "В виде кода".

Алгоритм 5.N: Для каждого реквизита с `indexing == INDEX_WITH_ADDITIONAL_ORDER`
при `codeLength != 0 && mainPresentation == AS_CODE` — создать индекс состава
[ОРНР…] + Реквизит_N + Код + Ссылка.

Статус: ✅

#### Правило 6 — [ОРРХ | ОРНР1 +] Реквизит + Наименование + Ссылка

Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение
"Индексировать с доп. упорядочиванием" и при этом свойство "Длина наименования" не равно 0,
а свойство "основное представление" равно "В виде наименования".

Алгоритм 6.N: Для каждого реквизита с `indexing == INDEX_WITH_ADDITIONAL_ORDER`
при `descriptionLength != 0 && mainPresentation == AS_DESCRIPTION` — создать индекс состава
[ОРНР…] + Реквизит_N + Наименование + Ссылка.

Статус: ✅

#### Правило 7 — [ОРРХ | ОРНР1 +] Реквизит

Условие: Справочник включен в критерий отбора через реквизит "Реквизит".

Алгоритм 7.N: Для каждого реквизита, входящего в состав (content) любого критерия отбора
конфигурации вместе со ссылкой на данный справочник, — создать индекс состава
[ОРНР…] + Реквизит_N.

Статус: ✅

#### Правило 8 — [ОРРХ | ОРНР1 +] PredefinedID

Условие: Индекс по идентификатору предопределенного объекта метаданных.

Статус: ❌ Не реализуется.

## Регистр сведений

### Непериодический регистр сведений

#### Правило 1 — [ОРРХ | ОРНР1 +] Измерение1 + [Измерение2 +...] (Кластерный)

Условие: Есть хоть одно измерение регистра. Индекс, включающий все измерения в том порядке,
в котором они заданы при конфигурировании. Индекс кластерный, если регистр независимый.

Алгоритм 1.1: Если у регистра есть хотя бы одно измерение — создать индекс состава
[ОРНР…] + Измерение1 + … + ИзмерениеM (все измерения по порядку задания).
Кластерный ⇔ `writeMode == INDEPENDENT`.

Статус: ✅

#### Правило 2 — [ОРРХ | ОРНР1 +] ИзмерениеN + Измерение1 + [Измерение2 +...]

Условие: Измерению "ИзмерениеN" задано свойство "Индексировать" или свойство "Ведущее"
и при этом это не первое и не единственное измерение. Индекс, включающий все измерения.
Первое поле - ИзмерениеN, затем все остальные измерения в том порядке, в котором они заданы
при конфигурировании.

Алгоритм 2.N: Для каждого измерения N, кроме первого и единственного, с
`indexing == INDEX || master` — создать индекс состава [ОРНР…] + ИзмерениеN +
Измерение1 + … (остальные измерения по порядку задания).

Статус: ✅

#### Правило 3 — [ОРРХ | ОРНР1 +] Реквизит + Измерение1 + [Измерение2 +...]

Условие: Реквизиту "Реквизит" задано свойство "Индексировать". Индекс в котором первое поле -
Реквизит, затем все измерения в том порядке, в котором они заданы при конфигурировании.

Алгоритм 3.N: Для каждого реквизита с `indexing == INDEX` — создать индекс состава
[ОРНР…] + Реквизит_N + Измерение1 + … (все измерения по порядку задания).

## Исключённые индексы (сводно)

Следующие группы индексов документации в модели не строятся:

| Группа | Причина |
| --- | --- |
| Индексы по PredefinedID (все объекты) | Решением задачи индекс предопределённости не моделируется |
| Таблицы опций всех объектов («Идентификатор») | Служебные таблицы исключены |
| Регистр накопления: таблицы остатков и оборотов, агрегаты (агрегаты, статистика, опции сети агрегатов, буфер новых оборотов, новые обороты, коды измерений, сеть агрегатов) | Служебные таблицы исключены |
| Регистр сведений: таблицы итогов срезов (ИтогиСрезПервых, ИтогиСрезПоследних) | Служебные таблицы исключены |
| Регистр бухгалтерии: таблицы итогов по счету и между счетами, таблица субконто | Служебные таблицы исключены |
| Регистр расчета: таблица перерасчета, таблица фактических периодов действия | Служебные таблицы исключены |
| Последовательности: таблица границ последовательности | Служебные таблицы исключены |
| Бизнес-процессы: таблица точек маршрута | Служебные таблицы исключены |
| Сервисы интеграции, история данных | Служебные таблицы, вне скоупа задачи |

## Зафиксированные интерпретации

1. Хэш разделителей (ОРРХ): во всех индексах вместо выбора «поле разделителя или хэш»
   включаются все независимые разделители объекта.
2. Кластерность индекса по измерениям периодического регистра сведений — по аналогии
   с непериодическим: кластерный ⇔ регистр независимый.
3. Набор индексов регистра сведений с периодичностью «По позиции регистратора» заменяет
   обычный набор периодического регистра.
4. План счетов регистра бухгалтерии обязателен, поэтому индекс по счёту (Счет) создаётся всегда.
