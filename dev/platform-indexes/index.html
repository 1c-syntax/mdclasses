    Алгоритмы формирования платформенных индексов¶

    Документ фиксирует правила формирования индексов таблиц базы данных объектов метаданных и алгоритмы их расчёта в модели MDClasses. Для каждого объекта метаданных приведены правила, для каждого правила — полный состав индекса и условие из документации платформы, алгоритмы формирования и статус включения в модель.

    Документ является чек-листом трассировки: правило → алгоритм → ветка калькулятора → эталонный объект в тестах.

    Источник правил: 1С:Предприятие 8.3.27, методическая поддержка для разработчиков и администраторов (its.1c.ru, раздел «Индексы таблиц базы данных»).

    Общие соглашения¶

    Разделители¶

    Во все индексы объекта первыми полями входят общие реквизиты, являющиеся разделителями данного объекта в режиме «Разделять независимо»: общие реквизиты конфигурации, у которых свойство «Разделение данных» равно SEPARATE_INDEPENDENTLY и данный объект входит в их состав (список использования). В составе индекса обозначаются [ОРНР…].

    Часть условий документации описывает выбор между полем конкретного разделителя (ОРНР1) и полем хэш-функции значений разделителей (ОРРХ). Хэш (ОРРХ) — физическое представление индекса в СУБД и в модели не строится: во всех таких случаях в индекс включаются все независимые разделители объекта.

    Легенда¶

    • ✅ — правило включено в модель;
    • ❌ — правило исключено из модели с указанием причины;
    • codeLength, descriptionLength, numberLength, orderLength — соответствующие свойства длины объекта;
    • mainPresentation — свойство «Основное представление» (AS_CODE / AS_DESCRIPTION);
    • indexing — свойство «Индексировать» реквизита/графы (INDEX / INDEX_WITH_ADDITIONAL_ORDER);
    • master — свойство «Ведущее» измерения;
    • foldersOnTop — свойство «Размещать группы сверху»;
    • writeMode — режим записи регистра сведений (INDEPENDENT / RECORDER_SUBORDINATE);
    • periodicity — периодичность регистра сведений;
    • correspondence — свойство «Корреспонденция» регистра бухгалтерии;
    • actionPeriod — свойство «Период действия» регистра расчета.

    Справочник¶

    Основные индексы¶

    Правило 1 — [ОРНР1 + ... +] Ссылка (Кластерный)¶

    Условие: Всегда. В индекс входят поля независимых разделителей, которые разделяют этот справочник.

    Алгоритм 1.1: Создать индекс состава [ОРНР…] + Ссылка, кластерный.

    Статус: ✅

    Правило 2 — [ОРРХ | ОРНР1 +] Код + Ссылка¶

    Условие: Свойство "Длина кода" не равно 0. Если справочник разделяется одним независимым разделителем, тип которого не Строка, то индекс содержит поле этого разделителя. Если тип разделителя - Строка, или разделитель независимый и совместный, или разделителей больше одного, то индекс содержит поле значения хэш-функции значений разделителей. Это правило справедливо для всех индексов, в составе которых указано [ОРРХ | ОРНР1 +].

    Алгоритм 2.1: Если codeLength != 0 — создать индекс состава [ОРНР…] + Код + Ссылка. Выбор между полем разделителя и хэшем (часть условия про ОРРХ) не моделируется: включаются все независимые разделители объекта.

    Статус: ✅

    Правило 3 — [ОРРХ | ОРНР1 +] Наименование + Ссылка¶

    Условие: Свойство "Длина наименования" не равно 0.

    Алгоритм 3.1: Если descriptionLength != 0 — создать индекс состава [ОРНР…] + Наименование + Ссылка.

    Статус: ✅

    Правило 4 — [ОРРХ | ОРНР1 +] Реквизит + Ссылка¶

    Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение "Индексировать".

    Алгоритм 4.N: Для каждого реквизита справочника с indexing == INDEX — создать индекс состава [ОРНР…] + Реквизит_N + Ссылка.

    Статус: ✅

    Правило 5 — [ОРРХ | ОРНР1 +] Реквизит + Код + Ссылка¶

    Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение "Индексировать с доп. упорядочиванием" и при этом свойство "Длина кода" не равно 0, а свойство "Основное представление" равно "В виде кода".

    Алгоритм 5.N: Для каждого реквизита с indexing == INDEX_WITH_ADDITIONAL_ORDER при codeLength != 0 && mainPresentation == AS_CODE — создать индекс состава [ОРНР…] + Реквизит_N + Код + Ссылка.

    Статус: ✅

    Правило 6 — [ОРРХ | ОРНР1 +] Реквизит + Наименование + Ссылка¶

    Условие: Для реквизита "Реквизит" свойство "Индексировать" установлено в значение "Индексировать с доп. упорядочиванием" и при этом свойство "Длина наименования" не равно 0, а свойство "основное представление" равно "В виде наименования".

    Условие: Справочник включен в критерий отбора через реквизит "Реквизит".

    Алгоритм 7.N: Для каждого реквизита, входящего в состав (content) любого критерия отбора конфигурации вместе со ссылкой на данный справочник, — создать индекс состава [ОРНР…] + Реквизит_N.

    Индексы по PredefinedID (все объекты) Решением задачи индекс предопределённости не моделируется
    Таблицы опций всех объектов («Идентификатор») Служебные таблицы исключены
    Регистр накопления: таблицы остатков и оборотов, агрегаты (агрегаты, статистика, опции сети агрегатов, буфер новых оборотов, новые обороты, коды измерений, сеть агрегатов) Служебные таблицы исключены
    Регистр сведений: таблицы итогов срезов (ИтогиСрезПервых, ИтогиСрезПоследних) Служебные таблицы исключены
    Регистр бухгалтерии: таблицы итогов по счету и между счетами, таблица субконто Служебные таблицы исключены
    Регистр расчета: таблица перерасчета, таблица фактических периодов действия Служебные таблицы исключены
    Последовательности: таблица границ последовательности Служебные таблицы исключены
    Бизнес-процессы: таблица точек маршрута Служебные таблицы исключены
    Сервисы интеграции, история данных Служебные таблицы, вне скоупа задачи
    Поля ОРРХ (хэш разделителей), DimHash, Splitter, ХэшИзмерений, РазделительИтогов Физическое представление индексов в СУБД, в модели не строятся

    Зафиксированные интерпретации¶

    1. Хэш разделителей (ОРРХ): во всех индексах вместо выбора «поле разделителя или хэш» включаются все независимые разделители объекта.
    2. Кластерность индекса по измерениям периодического регистра сведений — по аналогии с непериодическим: кластерный ⇔ регистр независимый.
    3. Набор индексов регистра сведений с периодичностью «По позиции регистратора» заменяет обычный набор периодического регистра.
    4. План счетов регистра бухгалтерии обязателен, поэтому индекс по счёту (Счет) создаётся всегда.
